# ES Code removal plan: sixth pass

**Status:** Planned and authorized by the owner on 22 October 2026. Implementation has not started. The planning baseline is `566260c23e767c6b146ab9ad66477661df7fb27d`; the owner's `AGENTS.md` update is committed in that baseline and must be preserved. The [overall removal plan](ES_CODE_REMOVAL_PLAN.md) records the editor workflows to retain, and the [fifth pass](ES_CODE_REMOVAL_ROUND_5.md) records the most recent package baseline.

This pass removes three unused experiences from the personal desktop fork: Mermaid rendering inside notebooks, first-party voice features, and GitHub Cloud agent sessions. It is a source, registration, dependency, and release-payload cleanup. Do not infer a startup improvement from deleted files or package-size changes; measure startup separately if making a speed claim.

## Decisions and boundaries

| Area | Remove | Preserve and verify |
| --- | --- | --- |
| Mermaid notebook renderer | The `notebookRenderer` contribution, `notebook-out` build and packaged output, notebook-specific entry source, notebook context-menu conditions, and now-unused tests/docs/build filters in `mermaid-markdown-features`. | Mermaid rendering in ordinary Markdown preview, the optional rich Markdown editor, and chat/agent output. Keep the Mermaid extension itself and the generic notebook extension API. |
| First-party voice | Voice Mode, the voice window/widget and transcript views, chat voice conversation/playback, first-party speech-to-text and text-to-speech UI, dictation into chat/editor/terminal, onboarding, mic controls, voice-only settings/commands/keybindings/policies, and voice-only stored-state migrations. Remove the Foundry Local dictation SDK, native-runtime build/publish pipeline, and product stamp only after proving they have no other live consumers. | Typed chat and local Claude/Codex Agent Host sessions, text prompts, tool approvals, normal editor/terminal input, accessibility features unrelated to speech, and general extension APIs. Audit the proposed `vscode.speech` provider bridge before changing it; preserve extension compatibility unless the implementation proves it is exclusively first-party and records the compatibility decision. Do not delete existing user transcript files merely because their UI is removed. |
| GitHub Cloud agents | GitHub Cloud sandbox session creation, discovery, feed, connection/reconnection, authentication-token sealing, cloud models, repository picker, cloud session UI/settings/commands, telemetry, and cloud-only history/trace types after consumer audit. Handle persisted Cloud sessions and old links without retrying a removed service or disturbing local sessions. | Regular GitHub authentication and Git/SSH workflows; local Agent Host and Claude/Codex providers; ordinary chat/session APIs; Dev Containers CLI, headless server, local port access, and remote extension-host infrastructure. Retain generic remote Agent Host support for SSH, WSL, WebSocket, or Dev Containers where it has a live non-cloud consumer. Do not treat `missionControl` names as automatically cloud-only. |
| Platforms and installation | Remove orphaned voice/cloud build inputs and release artifacts on supported desktop platforms. | macOS desktop packaging now; Windows and Linux source/build paths for possible later packages. The installed `/Applications/ES Code.app` is not an implementation target for this pass. |

The cloud scope means **GitHub Cloud sandbox/coding-agent sessions**, not the local Claude/Codex Agent Host, all remote Agent Host connections, or ordinary GitHub sign-in. The voice scope includes both on-device dictation and cloud voice features. Shared speech protocol or extension API types may remain when third-party consumers or compatibility require them; document each retained path and its consumer.

## Baseline evidence and audit starting points

- The fifth-pass disposable macOS arm64 package contains `18,660 KiB` under `extensions/mermaid-markdown-features/notebook-out`. That is package disk allocation for this one directory, not an expected startup saving. [`extensions/mermaid-markdown-features/package.json`](extensions/mermaid-markdown-features/package.json) still contributes a notebook renderer, and [`esbuild.webview.mts`](extensions/mermaid-markdown-features/esbuild.webview.mts) builds separate Markdown preview, notebook, and chat outputs. [`build/filters.ts`](build/filters.ts) names the notebook output. Do not remove Markdown preview or chat chunks while cleaning that package.
- Voice has more than one surface. [`chat.shared.contribution.ts`](src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts) registers dictation settings, voice actions/services, and a `BlockRestore` contribution that instantiates chat speech-to-text. [`workbench.desktop.main.ts`](src/vs/workbench/workbench.desktop.main.ts) registers local transcription, and [`workbench.common.main.ts`](src/vs/workbench/workbench.common.main.ts) registers the speech service. Also audit `src/vs/workbench/contrib/{agentsVoice,speech,codeEditor/browser/dictation,terminal}`, `src/vs/workbench/contrib/chat/{browser/{speechToText,voiceClient,voiceInputMode},common/{voiceClient,voicePlaybackService,voiceChatService.ts}}`, `src/vs/platform/localTranscription`, and `src/vs/workbench/services/localTranscription`. Some `agentsVoice` source may already be unreachable from shipped entry points; prove packaging reachability before attributing savings to it.
- Voice release plumbing includes `foundry-local-sdk` in [`package.json`](package.json), its postinstall patch in [`build/npm/postinstall.ts`](build/npm/postinstall.ts), `build/dictation-runtime`, the CI dictation-runtime templates, [`build/gulpfile.vscode.ts`](build/gulpfile.vscode.ts), [`build/next/index.ts`](build/next/index.ts), and macOS universal packaging. Audit `@github/copilot-sdk` and `@vscode/copilot-api` separately; earlier passes retained them for live local Agent Host consumers.
- GitHub Cloud is currently disabled by default in [`remoteAgentHost.contribution.ts`](src/vs/workbench/contrib/chat/browser/remoteAgentHost/remoteAgentHost.contribution.ts), but its services and contributions are registered after restore. Start at `src/vs/workbench/contrib/chat/browser/remoteAgentHost/{cloudSandbox*,editorCloudSandboxContribution,remoteAgentHost.contribution}.ts`, `src/vs/platform/agentHost/common/{cloudSandboxAgentHost,remoteAgentHostService}.ts`, the cloud session type in `chatSessionsService.ts`, and cloud traces in chat service/widget code. Audit `src/vs/platform/agentHost/node/missionControl/missionControlAuthentication.ts` before changing it: the fourth pass retained a live local credential consumer there.
- The fifth pass did not verify an editor **Reopen in Container** flow because no compatible connector was available. Preserve the shared remote/server paths and keep that limitation explicit. Previous runtime checks did verify Dev Containers CLI execution and localhost HTTP access.

A normal `.md` preview renders a Mermaid diagram, a rich Markdown editor can still open a Markdown file, and Mermaid chat output still renders where the current app supports it. - No first-party Voice Mode, dictation, mic, playback, voice transcript view, onboarding, voice-only settings, commands, or keybindings remain registered in the desktop app. No removed voice worker, model download, CDN stamp, or SDK is packaged. Check Windows/Linux source paths, but record unbuilt platforms explicitly.
