# ES Code removal plan: sixth pass

> Historical implementation record. [ES Code: product direction and removal record](ES_CODE_REMOVAL_PLAN.md) is the current decision source; later choices supersede any older retention requirements here.

**Status:** Implemented and validated in the worktree on 23 October 2026, with the runtime limits recorded below. The planning baseline was `566260c23e767c6b146ab9ad66477661df7fb27d`; implementation started from clean commit `aa4057e4acc5e0d59d004e51f7a750ff015e2b4f`. The owner's `AGENTS.md` update was already committed and is preserved. The [overall removal plan](ES_CODE_REMOVAL_PLAN.md) records the editor workflows to retain, and the [fifth pass](ES_CODE_REMOVAL_ROUND_5.md) supplies the comparison package.

**Later owner decision, 23 October 2026:** AI should come only from installed extensions. This supersedes this pass's original requirement to retain built-in local Claude/Codex Agent Host sessions and typed workbench chat. The original scope and acceptance record below remain as historical evidence; the extension-only follow-up and its current limits are at the end of this file.

This pass removes three unused experiences from the personal desktop fork: Mermaid rendering inside notebooks, first-party voice features, and GitHub Cloud agent sessions. It is a source, registration, dependency, and release-payload cleanup. Do not infer a startup improvement from deleted files or package-size changes; measure startup separately if making a speed claim.

## Decisions and boundaries

| Area | Remove | Preserve and verify |
| --- | --- | --- |
| Mermaid notebook renderer | The `notebookRenderer` contribution, `notebook-out` build and packaged output, notebook-specific entry source, notebook context-menu conditions, and now-unused tests/docs/build filters in `mermaid-markdown-features`. | Mermaid rendering in ordinary Markdown preview, the optional rich Markdown editor, and chat/agent output. Keep the Mermaid extension itself and the generic notebook extension API. |
| First-party voice | Voice Mode, the voice window/widget and transcript views, chat voice conversation/playback, first-party speech-to-text and text-to-speech UI, dictation into chat/editor/terminal, onboarding, mic controls, voice-only settings/commands/keybindings/policies, and voice-only stored-state migrations. Remove the Foundry Local dictation SDK, native-runtime build/publish pipeline, and product stamp only after proving they have no other live consumers. | Typed chat and local Claude/Codex Agent Host sessions, text prompts, tool approvals, normal editor/terminal input, accessibility features unrelated to speech, and general extension APIs. Audit the proposed `vscode.speech` provider bridge before changing it; preserve extension compatibility unless the implementation proves it is exclusively first-party and records the compatibility decision. Do not delete existing user transcript files merely because their UI is removed. |
| GitHub Cloud agents | GitHub Cloud sandbox session creation, discovery, feed, connection/reconnection, authentication-token sealing, cloud models, repository picker, cloud session UI/settings/commands, telemetry, and cloud-only history/trace types after consumer audit. Handle persisted Cloud sessions and old links without retrying a removed service or disturbing local sessions. | Regular GitHub authentication and Git/SSH workflows; local Agent Host and Claude/Codex providers; ordinary chat/session APIs; Dev Containers CLI, headless server, local port access, and remote extension-host infrastructure. Retain generic remote Agent Host support for SSH, WSL, WebSocket, or Dev Containers where it has a live non-cloud consumer. Do not treat `missionControl` names as automatically cloud-only. |
| Platforms and installation | Remove orphaned voice/cloud build inputs and release artifacts on supported desktop platforms. | macOS desktop packaging now; Windows and Linux source/build paths for possible later packages. The installed `/Applications/ES Code.app` is not an implementation target for this pass. |

The cloud scope means **GitHub Cloud sandbox/coding-agent sessions**, not the local Claude/Codex Agent Host, all remote Agent Host connections, or ordinary GitHub sign-in. The voice scope includes both on-device dictation and cloud voice features. Shared speech protocol or extension API types may remain when third-party consumers or compatibility require them; document each retained path and its consumer.
