# ES Code: product direction and removal record

**Current decision source, 23 October 2026.** This document records the editor ES Code is intended to be and the current state of the removal work. It supersedes conflicting retention language in the historical pass records linked below. The installed macOS arm64 app at `/Applications/ES Code.app` contains runtime source commit `408104fe972e9b35de39269df41a1241bd89df23`; later documentation commits do not change that binary. The previous app is preserved at `/Applications/ES Code.app.backup-before-scm-sidebar-20261023`, and the older backup remains at `/Applications/ES Code.app.backup-before-extension-only-20261023`. Installation did not replace the normal profile or user transcript files; the new app was then launched with the normal profile.

## The editor we are making

ES Code is a personal, local-first desktop code editor. It keeps VS Code's editing, languages, Source Control, terminal, Run/Debug/Test, and extension platform. The base app stays focused; optional capabilities come from installed extensions. "Local-first" does not mean offline-only: Open VSX, GitHub sign-in, Git operations, and installed extensions may use network services when the owner chooses them.

The owner confirmed these choices on 23 October 2026:

- **Extension-only AI.** No bundled Copilot provider, first-party local Claude/Codex Agent Host experience, GitHub Cloud agent sessions, or first-party voice and dictation. Keep general chat and language-model extension APIs (`vscode.chat` and `vscode.lm`) and repair their current bridge errors so extensions can supply AI. An extension's independent webview is also supported.
- **Local development.** Keep local Dev Containers CLI, headless server, remote extension-host infrastructure needed for local containers, and localhost port access. Leave GitHub Codespaces, Remote SSH, public tunnels, Agent Host sharing, and browser-hosted ES Code removed. The editor's **Reopen in Container** flow is still unverified because no compatible connector is available.
- **Git and GitHub.** Keep the built-in Git/Source Control experience, bundled GitHub authentication provider, and GitHub-specific actions such as repository publishing. Git over SSH is handled by the system Git executable and the user's SSH configuration; it does not require signing in through ES Code. GitHub sign-in remains useful for GitHub actions and extensions that request it.
- **Simple ownership.** Keep one internal default profile, user and workspace settings, manual app installation, Open VSX extension installation, Tokyo Night and Nomo Dark defaults, shell-driven terminal completion, Markdown/Mermaid, and bundled language support. No Settings Sync, profile-management UI, or built-in updater.

macOS desktop packaging is the current release target. Windows and Linux desktop source and build paths remain for possible later packages, but their latest packages have not been built. Source and test code is not automatically a shipped feature: distinguish removed code, disabled registration, excluded release payload, and a validated runtime behavior before declaring work complete. Audit shared services before deleting them. Do not infer startup speed from source deletion or package size.

## Generic AI extension API bridge — 23 October 2026

The extension host always constructs the chat, language-model, tool and output-renderer proxies. The workbench had disabled their main-thread actors, omitted the LM/tool/chat/MCP customer registrations, and omitted the output-renderer customer that shares `MainThreadWebviews`. That produced `Unknown actor MainThreadChatSkills` (the protocol actor for language-model tools) and `MainThreadChatOutputRenderer`. The repair restores those generic actors and their service registrations. The output renderer is constructed alongside the shared webview manager. `chat.disableAIFeatures` is registered with default `true` for first-party AI; it does not gate extension API actors. The full chat workbench contribution is still absent, and the Agent Host dependencies needed by generic services resolve to null implementations rather than starting first-party Claude/Codex sessions. The shared chat session and participant registries are available for extensions; no bundled provider was added.

Validation from this work area:

- `npm run typecheck-client`, `npm --prefix build run typecheck`, changed-file ESLint, `git diff --check`, and `scripts/test.sh --grep 'MainThreadChatOutputRenderer|MainThreadLanguageModels|MainThreadChatAgents2'` passed. The focused Electron run contains 10 passing tests, including a new output-renderer registration/disposal test.
- `VSCODE_BUILD_ROOT=/private/tmp/es-ai-bridge-build npm run gulp vscode-darwin-arm64-min` passed. The first package attempt could not resolve Electron's release URL (`ENOTFOUND`). For the successful run, the ignored local `@vscode/gulp-electron` downloader temporarily used the already cached Electron 43.7.7 macOS arm64 ZIP. Its SHA-256 was `9327d8ba5bc9e279d1a2f7da90235301c65a2e80eb4ad3bc5610d28d483340f9`, matching `build/checksums/electron.txt`; the downloader was restored byte for byte after packaging.
- The disposable `ES Code.app` contains an arm64 Mach-O launcher, passed ad hoc signing and `codesign --verify --deep --strict`, and passed all six `product.json` payload SHA-256/base64 checks: preload JS, workbench JS/CSS, extension-host JS, and workbench HTML/JS. Its packaged `package.json`, `node_modules.asar`, and unpacked node-module payload exclude `@anthropic-ai/claude-agent-sdk`, `@anthropic-ai/sdk`, `@github/copilot-sdk`, `@hpke/core`, `@openai/codex`, and `@vscode/copilot-api`. No Copilot extension is bundled.
- `open -na` launched that package with separate `/private/tmp/es-ai-bridge-smoke/package-profile`, `package-extensions` and `package-shared` directories. A disposable development extension called `vscode.chat.createChatParticipant`, `vscode.chat.registerChatOutputRenderer`, `vscode.lm.registerLanguageModelChatProvider`, `selectChatModels`/`sendRequest` (streamed `bridge-ok`), `registerTool`/`invokeTool` (returned `tool-ok`), `registerIgnoredFileProvider`/`fileIsIgnored` (returned `true`), and `registerMcpServerDefinitionProvider`. All seven steps completed with no extension errors; it read `chat.disableAIFeatures` as `true`. The isolated renderer and extension-host logs contained neither unknown-actor error. The launch window showed the ordinary ES Code start screen with no built-in AI provider or Copilot control. Source registration audit found no restored first-party Copilot menu contribution; macOS native menu inspection was unavailable because the automation process lacks Assistive Access.

The smoke extension registered a chat participant and output renderer, but did not deliver a participant request or render a chat output item through a chat surface. It registered an MCP definition provider without starting an MCP server. Proposed chat-session controllers/content providers remain behind the disabled `MainThreadChatSessions` actor: that actor directly depends on `IAgentSessionsService`, whose full contribution also enables the removed first-party agent-session workbench. Those proposed APIs need a separate consumer audit and service split before being advertised as supported. The other disabled first-party/proposed chat actors were not restored. Compatibility with other third-party extensions remains unproven. The installed app now includes the bridge repair, but the seven-step bridge smoke was not repeated on that installed bundle. No startup timing was measured.

## Open work

Exercise a chat participant request and output-renderer item in an extension-provided chat surface, and an MCP provider supplying a real definition, before claiming those paths end to end. The automated installed-app check could not enable extensions in its Restricted Mode window: automatic approval review rejected clicking **Trust** because it would enable tasks, debugging and all extensions. No trust setting was changed.
3. **Local container editor flow — owner check:** The owner will test the Dev Containers editor workflow and does not need agent follow-up on the connector for now. **Reopen in Container**, editor commands and the remote extension host remain unverified; CLI and localhost checks do not establish this workflow.
4. **Authenticated and cross-platform checks:** Exercise GitHub sign-in and an authenticated Git operation when credentials are available. Build Windows and Linux packages before claiming those releases work.
5. **Further source cleanup and performance:** Audit dormant Agent Host/Copilot source and source/test dependencies before deleting them; the installed app already excludes their inactive SDK payload. Measure comparable startup timings before reporting a speed change.
